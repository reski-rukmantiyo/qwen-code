# Submit Function - Summary

## Overview
The submit function is an OpenSpec command that allows users to submit new change proposals with activity type and description. It integrates with the existing OpenSpec workflow to generate implementation tasks based on the provided information.

## Usage
```
/openspec submit [change-name] [activity] [description]
```

### Parameters
- `change-name`: The name of the change directory under `openspec/changes`
- `activity`: Either "bugs" or "features" to categorize the submission
- `description`: A detailed description of the change or fix

### Interactive Mode
If no parameters are provided, the submit command operates in interactive mode:
1. Lists available changes (directories under `openspec/changes` excluding `archive`)
2. Prompts for activity type (bugs/features)
3. Prompts for description
4. Generates and appends tasks to the change's `tasks.md` file

## Relationship to OpenSpec Change Structure
This implementation follows the standard OpenSpec change structure where each change directory contains:
- `proposal.md` - Technical proposal and implementation approach (generated by changeCommand.ts)
- `design.md` - Design decisions and technical details (generated by changeCommand.ts)
- `tasks.md` - Implementation tasks (generated by changeCommand.ts, updated by submit function)

The submit function works with existing changes created by the changeCommand.ts function. When a user submits a new activity with a description, the submit function:
1. Reads the existing proposal.md and design.md files
2. Generates new implementation tasks based on the activity type and description
3. Appends these tasks to the existing tasks.md file

This maintains the workflow where:
1. Users first create a change with `/openspec change <change-name> [description]` (generates proposal.md, design.md, tasks.md)
2. Users then submit additional tasks with `/openspec submit <change-name> <activity> <description>` (updates tasks.md)
